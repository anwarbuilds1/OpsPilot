# AI Agent Security & Guardrails

> **Component:** AI Investigation Engine  
> **Status:** Mandatory Security Specification

This document details the security constraints governing the AI Investigation Agent.

---

## 1. Zero Infrastructure Authorization

OpsPilot enforces a strict architectural boundary: **The LLM is never the authorization authority.**

- Authorization decisions (can this user deploy this service, can this tenant view these logs) are made **exclusively** by compiled TypeScript code in the API and worker layers.
- The AI Agent does not possess IAM credentials, database admin tokens, or SSH keys.
- The AI Agent cannot grant itself permissions or bypass tenant boundaries.

---

## 2. Tool Execution Allowlist

The agent can only invoke functions registered in its explicit tool allowlist:
1. `get_service_details`
2. `get_recent_deployments`
3. `get_deployment_details`
4. `get_application_logs`
5. `query_metrics`
6. `get_container_status`
7. `get_recent_commits`
8. `get_health_status`
9. `get_incident_timeline`

Any attempt by the model to call arbitrary function names or access shell APIs is caught by the AI Gateway, rejected with an error message, and recorded in the audit log.

---

## 3. Human Approval Gate for Remediation

Remediation proposals generated by the AI (such as deployment rollbacks or code diffs) are purely advisory. They are presented to human engineers in the web UI and as GitHub Pull Requests. Production execution requires an authenticated human click or GitHub PR merge.
