# Incident Investigation: End-to-End Walkthrough

> **Scenario:** Database Connection Pool Starvation following Deployment #108  
> **Affected Service:** `payments-api` on AWS ECS Fargate  
> **Severity:** Critical (HTTP 500 Spike & Failing Health Checks)

This document provides a realistic, step-by-step trace of how OpsPilot detects, correlates, and investigates a real-world production outage.

---

## 1. Incident Timeline & Detection

- **10:15 UTC:** Marcus pushes commit `8fa2b10` to `main`: *"Refactor database pool configuration"*.
- **10:17 UTC:** GitHub webhook triggers OpsPilot Deployment #108.
- **10:20 UTC:** Deployment #108 stabilizes and reports healthy on AWS ECS.
- **10:23 UTC:** Traffic increases. Application logs begin displaying `SequelizeConnectionError: ResourceRequest timed out`.
- **10:25 UTC:** Synthetic health checks fail 3 consecutive probes (HTTP 500).
- **10:25:05 UTC:** OpsPilot Incident Engine creates **Incident #INC-402** (`Critical`) and dispatches a background investigation job to the AI Investigation Worker.

---

## 2. Multi-Turn AI Investigation Trace

### Turn 1: Initial Context & Tool Selection
The orchestrator initializes the session with the incident brief:
- Service: `payments-api`
- Alert: Health check failed 3 consecutive times with HTTP 500
- Breach timestamp: `2026-11-01T10:25:00Z`

**AI Model Action:**
```json
{
  "name": "get_incident_timeline",
  "arguments": { "incidentId": "inc-402" }
}
```
**Tool Result:** Returns timeline showing Deployment #108 completed at 10:20 UTC, just 5 minutes before the failure.

---

### Turn 2: Querying Application Logs
The model notices the deployment correlation and immediately inspects logs around the breach:

**AI Model Action:**
```json
{
  "name": "get_application_logs",
  "arguments": {
    "serviceId": "5e6f7a8b",
    "fromTimestamp": "2026-11-01T10:21:00Z",
    "toTimestamp": "2026-11-01T10:26:00Z",
    "searchQuery": "ERROR"
  }
}
```
**Tool Result:**
```text
[10:23:45Z] ERROR: SequelizeConnectionAcquireTimeoutError: Connection acquisition timed out after 10000ms
[10:24:12Z] ERROR: ResourceRequest timed out; pool is currently at maximum capacity (2/2 active connections)
[10:24:30Z] ERROR: Health probe failed: Database query SELECT 1 timed out
```

---

### Turn 3: Commit Diff Inspection
The model identifies database pool exhaustion as the symptom and inspects the commit diff of Deployment #108 to find the cause:

**AI Model Action:**
```json
{
  "name": "get_recent_commits",
  "arguments": {
    "serviceId": "5e6f7a8b",
    "commitSha": "8fa2b10"
  }
}
```
**Tool Result:**
```diff
--- a/src/config/database.ts
+++ b/src/config/database.ts
@@ -14,7 +14,7 @@ export const dbConfig = {
   pool: {
-    max: 20,
+    max: 2,
     min: 0,
     acquire: 10000,
     idle: 10000
   }
 };
```

## 4. Human Verification & Rollback Resolution

1. On-call engineer Sarah receives the incident notification with the AI report summary in Slack.
2. Sarah clicks the incident link, reviews the commit diff and log evidence in the OpsPilot dashboard, and verifies that the hypothesis is correct.
3. Sarah clicks **"Rollback to Deployment #107"**.
4. OpsPilot updates the ECS service back to revision `:41`.
5. Within 45 seconds, health check probes return `HTTP 200 OK`.
6. Incident #INC-402 transitions automatically from `Mitigating` to `Resolved`.
